# ------------------------------------------------------------------------------
# OPTIONAL — GPU voice acceleration (Phase 7 speed round, 2026-07-15)
# ------------------------------------------------------------------------------
# By default STT (ctranslate2) and TTS (Kokoro/onnxruntime) run on CPU — a plain
# `pip install -r requirements.txt` needs NO CUDA. On a machine with an NVIDIA
# GPU you can make both engines near-instant (seconds → sub-second). The code
# auto-detects CUDA and falls back to CPU on any failure (app/core/gpu_bootstrap.py
# + the stt_device/tts_device settings), so this is purely additive.
#
# faster-whisper's ctranslate2 already ships CUDA support; only onnxruntime and
# the CUDA math libraries must be added. onnxruntime-gpu and onnxruntime CANNOT
# coexist (same package dir), and faster-whisper/fastembed pull CPU `onnxruntime`
# transitively — so install the GPU stack imperatively with --no-deps AFTER the
# base requirements (do NOT add these lines above; they'd conflict):
#
#   pip uninstall -y onnxruntime
#   pip install --no-deps onnxruntime-gpu==1.22.0 \
#       nvidia-cudnn-cu12==9.24.0.43 nvidia-cublas-cu12==12.9.2.10
#
# Version pins that matter (verified on Windows 11, Python 3.11, RTX 3060):
#   - onnxruntime-gpu==1.22.0  → CUDA 12.x build. DO NOT use 1.27.x: it requires
#                                CUDA 13 (looks for cublasLt64_13.dll) and its
#                                CUDA EP silently falls back to CPU on a CUDA-12
#                                box.
#   - nvidia-cudnn-cu12 9.x    → cuDNN 9, serves BOTH ctranslate2 and onnxruntime.
#   - nvidia-cublas-cu12 12.x  → cuBLAS 12; a system CUDA 12.x toolkit's cuBLAS
#                                also works (gpu_bootstrap registers either).
# fastembed keeps running on CPU (bge-small is tiny) — the GPU is reserved for
# Whisper + Kokoro where latency matters.

# ------------------------------------------------------------------------------
# OPTIONAL — screen OCR for the Context Layer (Phase 8, screen sensing)
# ------------------------------------------------------------------------------
# Screen OCR (app/core/screen_ocr.py) is OFF by default and opt-in per session,
# and its engine import is lazy — so a plain `pip install -r requirements.txt`
# does NOT need this, and the app runs fine without it (enabling OCR without it
# just returns a clean "could not read the screen" error). Install it only if
# you actually want on-screen context sensing:
#
#   pip install rapidocr-onnxruntime==1.3.24        # CPU-only box: plain install
#
# On a GPU box (you installed onnxruntime-gpu above), rapidocr declares the CPU
# `onnxruntime` as a dep and would clobber it — install rapidocr WITHOUT pulling
# onnxruntime (it reuses the resident onnxruntime-gpu), then its other runtime
# deps explicitly:
#
#   pip install --no-deps rapidocr-onnxruntime==1.3.24
#   pip install opencv-python-headless pyclipper shapely Pillow PyYAML six
#
# RapidOCR runs the OCR models on whatever onnxruntime is installed (CPU or the
# CUDA EP), so screen OCR rides the same GPU acceleration as the voice engines.

# OPTIONAL — unpacked browser extensions (e.g. uBlock Origin), 2026-07-22.
# Drop each extension into its own subdirectory of:
#
#   ~/.jarvis/browser_extensions/<name>/     (with manifest.json directly inside)
#
# Off by default (an empty dir adds nothing). Use uBlock Origin LITE (Manifest V3):
# current Chrome disables MV2 extensions, so classic uBlock may load-but-disable.
# Get the unpacked build from its GitHub releases and unzip into the folder above.
#
# IMPORTANT — WHERE IT ACTUALLY LOADS (proven live 2026-07-22): the extension
# loads ONLY in the NORMAL (non-automation) windows Jarvis opens — the clean
# sign-in / hand-off windows AND the watch/play media window
# (_default_clean_launcher / _default_clean_media_launcher, both via
# _extension_load_args). It does NOT load in the AGENT-LOOP window: that window is
# driven over the DevTools protocol (CDP), and current Chrome REFUSES to load an
# unpacked extension in any CDP-controlled browser as a security measure
# (chrome://extensions shows zero, no extension service worker registers, a known
# ad script still loads — all four verified). This is Chrome policy, not a Jarvis
# limitation, and there is no clean bypass (Extensions.loadUnpacked is unavailable,
# --disable-features and the CDP tricks were ineffective).
#
# So there are TWO ad-blocking layers for the two phases of a browse:
#   FINDING  (agent loop, interceptor ON): browser_session.py Rule 0 / _AD_HOSTS
#            aborts known ad/tracker hosts before they load, so the agent never
#            sees or misclicks a fake "Play" ad on a streaming site.
#   WATCHING (clean media window, interceptor absent by design — streaming
#            throughput): uBlock in the normal window blocks the rotating pop-under
#            ad domains a static host list never keeps up with. A "play/watch" goal
#            hands the found video URL off to this window (open_media_window).
